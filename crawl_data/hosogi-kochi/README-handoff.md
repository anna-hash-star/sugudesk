# 細木病院 クロール ハンドオフメモ（ローカル実行用）

このメモは、Web版 Claude Code セッションで細木病院のクロールを試みた際の引き継ぎ資料。
**このWeb環境では外部ネットワークへ出られず（egressポリシーで全外部ホストが 403 拒否）、公式HPを1ページも取得できなかったため、クロール本体はローカルで実行する。** 以下は貼り付けるだけで着手できるよう、事前に確定できた情報をまとめたもの。

## 0. なぜローカルなのか（このセッションで判明したこと）

- **ネットワーク不通**: このWebセッションの egress プロキシが `www.hosogi-hospital.jp` を含む全外部ホスト（`example.com` / `google.com` / `wikipedia` でも同様）に `403 (policy denial)` を返す。curl も WebFetch も不通。手順書2章のクロールが物理的に実行できない。
- **クロールスキル未配置**: このリポジトリ（`anna-hash-star/sugudesk` = SuguDesk の Next.js アプリ本体）には `.claude/skills/crawl-clinic-data/` も `/crawl-clinic-data` コマンドも存在しない（`main`・履歴含め無し）。手順書が指すスキルは**クロール資材を持つ別リポジトリ**にある。
- 対応: 手順書§2の前提どおり、**ネットワークのある手元のマシンで、クロールスキルを含むクローン上で** Claude Code を起動して実行する。

## 2. ローカルでのクロール実行手順

1. **クロールスキルを含むリポジトリ**を最新化したクローンで、リポジトリ root からネットワークのある環境で Claude Code を起動
2. 以下をそのまま依頼:

```
/crawl-clinic-data
URL: https://www.hosogi-hospital.jp/
clinic_slug: hosogi-kochi
```

3. 生成物（手順書§2）を確認:
   - `crawl_data/hosogi-kochi/data.json` — 投入本体
   - `crawl_data/hosogi-kochi/data.xlsx` — 目視レビュー用（22シート）
   - `crawl_data/hosogi-kochi/summary.md` — 件数/取り漏れ/手動確認サマリ
4. 投入前の機械チェック（手順書§2.1）で `backend_dto=ok` / `decompose=ok` を確認:

```
bash .claude/skills/crawl-clinic-data/scripts/validate_crawl_json_dotnet.sh crawl_data/hosogi-kochi/data.json
```
