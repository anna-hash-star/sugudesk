## 1. 販売チャネル・契約の変化

### 1.1 GIMIC との販売代理契約（今月開始）

- 上場企業の株式会社 GIMIC（医療機関 約7,000 と取引）と**販売代理契約**を締結。
- GIMIC 側の営業・カスタマーサクセスが SuguDesk を販売してくれる。
- **対象は SaaS ライトプランのみ**。
  - 売値: 月額 ¥4,000 / 導入費 ¥100,000。
  - GIMIC へのレベニューシェアは無し。
- **オペレーション設計（重要）**:
  - CS は**メールのみ**で最小化（運用コストを線形に膨らませない）。
  - **オンボーディングは有償**（工数に対価をつける）。
- 今後、GIMIC の連携商材としての**深い提携**を見据える（時期は 2026年7〜8月以降）。

### 1.2 大規模病院（800床）への無料トライアル

## 4. 開発体制

- エンジニアは **1名（本業を持つ副業／業務委託）**。
- 先月の稼働は日中以外で **約190時間**（当初計画 月64.5h の約3倍）。
- **課題**: リリース後の障害が**日中に発生した際の一次対応**ができない。
  - 緩和材料: Widget は障害時に**電話番号フォールバック**する設計のため、ボット停止＝医療現場停止にはならない（劣化対応）。
  - 対応方針案: 障害ランブック整備＋日中インシデントの SLA 付きリテイナー契約（フル増員はせず穴を塞ぐ）。

## 5. BPO 事業の方針

- **採用 BPO を主軸**に攻める（事務長代行より型化・外注しやすい）。
- クリニックのパイプラインあり。800床病院の経営企画担当の協力を得て立ち上げる。

## 6. 体制上のリスク（キャパシティ）

- 代表が**営業・CS・オンボーディングを兼務**しており、GIMIC と 800床の案件増で逼迫が見込まれる。
- 加えて、**代表の可処分時間が一時的に低下する見込み**があり、需要増とキャパ低下が重なる懸念。
- 対応方針案: フルタイム採用ではなく、まず**オンボ実働＋メール CS の一次対応を業務委託1名（月20〜30万目安）に切り出す**。
  - 営業・戦略は代表に残す（売上の源泉）。
  - バーン約100万/月・入金3,000万に対しランウェイは健全（委託追加でも20ヶ月超）。委託は浪費ではなく**売上エンジンと体制を守る保険**。

## 7. 黒字化（損益分岐）の論点

詳細な試算は `docs/損益分岐モデル.xlsx`（前提を変えれば全シート連動）を参照。

- 固定費 約93万/月（CEO報酬・エンジニア定常・インフラ・その他・GTM）を前提とすると、各商材が固定費を埋める力（限界利益/件・月）は概ね:
  - SaaS ライト（GIMIC ¥4,000）: 約 ¥600 … **単体では黒字化に寄与しない**（送客＋オンボ一時金が役割）
  - SaaS スタンダード（¥15,000）: 約 ¥7,600 … 単独黒字化に約123件
  - **BPO 事務長代行（¥150,000）: 約 ¥66,000 … 単独黒字化に約14件**
  - BPO 採用/集患（¥50,000）: 約 ¥20,000 … 単独黒字化に約47件
- **結論**: 黒字化は SaaS の台数ではなく、**BPO（特に事務長代行）の契約数**で決まる。
  - 営業の数値目標は「SaaS ◯件」ではなく「**BPO 事務長代行 ◯件**」に置く。
  - 黒字化を動かす最重要変数は「**事務長1人あたりの担当件数（オペ設計）**」と「**エンジニア定常費**」。
