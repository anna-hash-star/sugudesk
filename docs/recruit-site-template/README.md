# 医療系採用サイトの「型」設計書 v2

クリニック〜中小医療法人向けの採用サイトテンプレート。**実在の参考4サイトの構造分析**をベースに再構成した版。自社（SuguDesk）の強みであるチャットを「チャットで採用相談」として全体の導線に組み込む。ワイヤーの視覚版は `wireframe.html` を参照。

> 注記: 参考4サイトは本環境のネットワークポリシーによりページ本体の直接取得ができなかったため、構造は検索エンジンにインデックスされた下層URL群＋検索結果情報から再構成した。ページ内のセクション順序は推定を含む。

---

## 0. 前提の整理

| 項目 | 想定 |
|---|---|
| 発注者 | クリニック・中小医療法人（採用担当は院長 or 事務長が兼務） |
| ターゲット | 看護師（中途・パート中心）、医療事務、管理栄養士、臨床検査技師など |
| デバイス | スマホファースト |
| 自社の強み | **チャット（SuguDesk）** → 「チャットで採用相談」を型の標準装備にする |
| ゴール | 応募。中間ゴール2段: **チャット相談（最軽量）→ 見学（実地）** |

## 1. 参考4サイトの構造分析

### ① 自由が丘クリニックグループ（jc-recruit.jp）— グループ採用ポータル型
美容医療・化粧品グループの求人・転職サイト。

- 確認できた構造: `/about/group/`（グループ紹介）、`/work/`（仕事紹介）、`/work/welfare/`（福利厚生）、`/interview/nurse/`（職種別インタビュー）、`/recruitment/`（募集要項一覧）、`/recruitment/nurse_meguro/` など**職種×拠点**別の要項ページ
- 情報設計: **「知る(about) → 仕事を知る(work) → 人を知る(interview) → 条件を見る(recruitment)」の4層ファネル**
- 取り入れる点: 福利厚生を独立コンテンツ化／インタビューを職種別に持つ／要項URLを職種単位で分割（求人媒体・検索からの直接着地に強い）

### ② りつの内視鏡クリニック（ritsuno-recruit.com）— 単院・職種ハブ型
2019年開院の内視鏡専門クリニック。「スタッフ自身が幸せになる」を理念に掲げる。

- 確認できた構造: `/data/`（**数字でわかる**）、`/nurse/` `/doctor/` `/dietitian/` など**職種ごとの紹介ページ**、`/requirement/…`（職種別募集要項）、`/tour/`（**施設見学の流れ**）
- 情報設計: 職種ページ（働き方の紹介）と要項ページ（条件）を分離。見学を独立ページで「流れ」として明示
- 取り入れる点: 「数字でわかる」ページ／**見学をプロセスとして見せる**（見学の流れ＝不安の除去）／理念をスタッフ側に向ける（患者理念でなく「働く人の幸せ」）

### ③ 梶ヶ谷クリニック（kajigaya-clinic.com/recruit/）— 採用専用ミニマル型
川崎・内科系クリニック。患者向けサイトから**採用専用サイトを分離**。

- 確認できた構造: `/recruit/`（TOP）、`/recruit/clinic/`（医院紹介）、`/recruit/voice/`（スタッフの声）、`/recruit/job-description_nurse_part/` など**職種×雇用形態**別の要項ページ、`/recruit-news/`（お知らせ）
- 訴求内容: 駅徒歩2分、主婦・シニア活躍、有休消化率100%目標、**入職後3ヶ月のトレーナー制＋業務チェックリスト**
- 取り入れる点: 採用サイトの分離（医療広告GL回避の面でも正しい）／要項を雇用形態（常勤/パート）で分ける／教育体制を「制度名＋期間」で具体に書く

### ④ けいゆう病院（keiyu-hospital.com/recruit/）— 病院・多職種ポータル型
横浜の総合病院の採用サイト。

- 確認できた構造: `/recruit/`（TOP）→ `/recruit/nurses/`（職種大分類: 看護師・助産師・介護福祉士）→ 配下に `/education/`（教育体制）`/explanation/`（**病院説明会**）`/flow/`（募集要項）→ `/flow/career/ward/` `/flow/career/ope/` など**部署・雇用区分別**の詳細、`/entry/`（お問合せ・エントリー）
- 情報設計: 職種大分類の中に「教育・説明会・要項」を入れ子で持つ。説明会・見学会（オンライン含む）が独立コンテンツ
- 取り入れる点: 病院規模では職種を大分類→詳細の2階層にする／説明会・見学会をイベントとして常設／エントリーと問い合わせを同一ページに統合

### 4サイトの共通項（＝型に昇格させる要素）

1. **職種別ページが構造の中心**。4サイトすべてが職種（×拠点 or ×雇用形態）単位でURLを分割している。求職者は「自分の職種」しか読まない
2. **見学・説明会が独立した中間CV**（②③④）。応募の手前に必ず軽いステップがある
3. **スタッフの声/インタビューは全サイト標準装備**
4. **数字・具体の訴求**（②の/data/、③の有休100%・トレーナー制3ヶ月）
5. 問い合わせ手段は電話・メール・フォームのみ。**チャット相談はどのサイトにも無い → SuguDeskの明確な差別化ポイント**

## 2. 再構成：推奨サイト構成 v2

v1（TOP1枚LP＋下層3枚）から、**「TOP＋職種別ページ」を軸にしたハブ構造**へ更新。理由: 参考4サイトすべてが職種別ページ中心であり、求人媒体・指名検索からの着地先としても職種URLが必要なため。

### コンバージョン3段設計（今回の型の核）

```
軽い ◄────────────────────────────► 重い
チャットで採用相談  →  見学に行く  →  応募する
（匿名OK・即レス）    （30分・私服OK）  （フォーム/LINE）
```

- 参考4サイトは「見学→応募」の2段。本型はその手前に**チャット相談**を置き、電話しづらい・メールは重いと感じる求職者のゼロクリック接点を作る
- チャットは全ページ右下に常駐（SuguDeskウィジェット）＋TOPに専用セクション。FAQ・募集要項の疑問（「ブランク5年でも大丈夫？」「子どもの発熱時は？」）に即答し、会話の終端で見学・応募へ橋渡しする
- 運用面: 一次応答はボットが24時間対応、必要時に採用担当へ引き継ぎ。よくある質問はFAQと同一のナレッジを参照（SuguDeskの既存資産）

### サイトマップ（クリニック標準型）

```
TOP（ハブ）
├─ 職種別ページ /jobs/{nurse|clerk|dietitian|...}
│    └ 仕事内容・1日の流れ・先輩の声（抜粋）・募集要項（常勤/パートタブ）・CTA
├─ スタッフの声 /voice
├─ 見学・応募の流れ /flow        ← ②/tour/・④/explanation/ を簡略化して採用
├─ 応募・エントリー /entry
└─ ◎ チャットで採用相談          ← 全ページ常駐ウィジェット（ページではなく導線）
```

- ②式の「職種紹介ページと要項ページの分離」は採らない（クリニックの運用リソースでは2枚を保守できない）。**職種ページ1枚に働き方＋要項を統合**し、①③式の職種単位URLだけ踏襲
- 医院紹介・数字で見る・教育はTOPに集約（③のように下層化するのは更新が回る場合のみ）
- 病院規模（④型）の場合は `/jobs/` を「看護部門・医療技術部門・事務部門」の大分類2階層に拡張（wireframe.html §06参照）

### TOPページ構成 v2（10セクション）

| # | セクション | v1からの変更 | 参考元・根拠 |
|---|---|---|---|
| 1 | FV：実写＋コピー＋職種チップ＋**CTA3種（応募/見学/チャット相談）** | チャット相談を追加しCV3段をFVから提示 | 全サイト（実写FV）＋自社強み |
| 2 | 数字で見る（5タイル） | 維持 | ②/data/ が独立ページ化するほど機能している |
| 3 | 院長メッセージ・理念 | 「働く人に向けた理念」へ言い換え | ②「スタッフ自身が幸せに」 |
| 4 | **職種から探す（職種カード→ /jobs/ へ）** | 新設。v1の「1日の流れ」は職種ページへ移動 | 4サイト共通の職種中心構造 |
| 5 | スタッフの声（2〜3名抜粋→ /voice へ） | 維持 | ③/voice/・①/interview/ |
| 6 | 教育・福利厚生 | 「制度名＋期間」で具体化（例: トレーナー制・最初の3ヶ月） | ③の明文化・①/work/welfare/ |
| 7 | **チャットで採用相談** | 新設。チャットUIモック＋想定質問例を見せ、匿名OK・24時間を明示 | 4サイトに存在しない差別化。自社チャット資産 |
| 8 | 見学・応募の流れ（4ステップ: 相談→見学→面接→入職） | 「流れ」として図示する形に変更 | ②/tour/・④/explanation/ |
| 9 | FAQ →「解決しなければチャットへ」 | チャットに接続 | FAQとチャットのナレッジ共通化 |
| 10 | エントリー（フォーム4項目＋LINE＋チャット） | 維持＋チャット並列 | — |

※ スマホ下部固定バーは「応募する｜チャットで相談」の2ボタンに変更（v1は応募｜LINE）。

### 職種別ページ /jobs/{job} の型

1. 職種名＋雇用形態タブ（常勤/パート）… ③式
2. 仕事内容・1日の流れ（タイムライン）… v1のTOPから移動
3. この職種の先輩の声（1名抜粋）… ①式（職種別インタビュー）
4. 募集要項テーブル（職安法の明示9項目を内蔵、下記チェックリスト）
5. CTA: この職種に応募する／**この職種についてチャットで質問する**（職種コンテキストを引き継いでチャット起動）

### チャット「採用相談」の設計要件

- **配置**: 全ページ右下フローティング＋TOP§7＋FAQ末尾＋フォーム離脱時
- **初期メッセージ**: 「採用について匿名で相談できます。よくある質問: [ブランクがあっても大丈夫？][シフトの融通は？][見学だけでもいい？]」— チップ選択式で入力ハードルを下げる
- **ナレッジ**: FAQ・募集要項と同一ソース（二重管理しない）。SuguDeskの回答ルール資産を流用
- **エスカレーション**: 求職者が希望したら見学予約 or 採用担当への取次ぎへ。連絡先の取得はこの時点まで求めない（匿名性がこの導線の価値）
- **計測**: チャット起動率／相談→見学転換率／相談テーマ分布（募集要項の改善材料になる）

## 3. 法令チェックリスト（v1から変更なし・募集要項テンプレに内蔵）

- 業務内容 ＋ 変更の範囲（2024/4追加）
- 就業場所 ＋ 変更の範囲（2024/4追加）
- 契約期間／有期の場合は更新上限の有無・内容（2024/4追加）
- 試用期間の有無・期間・条件差
- 賃金（基本給・手当・固定残業の内訳）
- 労働時間・休憩・休日・時間外の有無
- 社会保険・労働保険の適用
- 受動喫煙防止措置
- 募集者の氏名または名称

採用サイトは患者への誘引性がないため医療広告ガイドライン対象外（③のように患者向けサイトと分離するのが安全）。なお**チャットの応答内容も募集条件に触れる場合は労働条件明示と矛盾しないようナレッジを要項と同期させる**こと。
