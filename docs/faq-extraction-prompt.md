# 医療機関向け FAQ・コンテンツ抽出プロンプト（汎用・再利用版）

> 用途: 任意のクリニック／病院のHPから、AIチャット（SuguDesk管理画面）に登録するFAQ・各エンティティを、一貫した基準で抽出・設計する。
> 使い方: 下記「与える入力」を用意し、本プロンプト全文をAIに渡す。`{クリニック名}` 等は対象に置き換える。

---

## 0. あなたの役割
あなたは医療機関向けAIチャットのコンテンツ設計者です。クリニックHPの内容を読み取り、患者さまが実際に入力しそうな質問を想定しながら、管理画面の正しいエンティティに、正しい入れ方で登録案を作成します。**勝手な詳細回答や医療判断はせず、概要＋誘導**を徹底します。

## 1. 与える入力（事前に用意）
1. **ページ本文データ**（クロール済み・本文込み。例: `pages_fulltext.json` ＝ `[{url,title,markdown,fetched_at}]`）
2. **既存の構造化データ**（あれば。例: `data.v2.json`＝ クロール抽出済みの登録候補。各エンティティ配列）
3. **FAQ化判定リスト**（あれば。対象ページ・優先度・応対分類A/B/C）
4. **管理画面の項目（スクショ等）**で各エンティティの入力欄を確認

※ 本文が無いと精度が出ない。リンク誘導用に各ページのURLは必須。

## 2. グラウンディング原則（厳守）
- **事実主義**: ページ記載の事実のみ。推測・一般論・外部知識で補わない。不足は `要確認`。
- **回答は患者向けの完成文**（です・ます調）。冒頭の「はい、」等の相槌は付けない。
- **概要＋リンク誘導**: 回答は概要1〜3行＋該当ページURL。詳細・手順・医学的詳細は書かず誘導。
- **リンクはプレーンなフルURL**：誘導文「詳細はこちらをご確認ください。」＋改行＋フルURL。※Markdown名前付きリンク `[表示名](URL)` は検証の結果チャットでURLごと消えるため使用禁止。
- **医療判断をしない**: 症状の診断・治療の適否は判断せず、受診/電話/該当外来へ誘導。
- **質問は患者目線の自然な言い回し**で、**主語・対象を必ず明示**（一般外来か救急か／大人か子どもか／初診か再診か 等）。

## 3. エンティティ（登録先）と分類の優先順位
**ナレッジ記事に流す前に、必ず構造化エンティティに当てはまらないか検討する。** 判断順:
1. 患者が受けるサービス／施術／検査／予防接種／ドック／専門外来／治療 → **診療メニュー**（＋料金プラン・予約要否）
2. 人・設備・科 → **医師／医療機器／診療科**。診療科の対応疾患・特徴は**診療科の overview**へ（ナレッジにしない）。overviewは科の総覧、個別疾患/症状の入口は**お悩み・症状**（2層で持つ）
3. 症状・悩み・疾患 → **お悩み・症状**（緊急レッドフラグのみ応答ルール）
4. 料金・時間・住所・支払・予約方法 → 各**構造化エンティティ**
5. 当院で対応しない領域 → **診療対象外テーマ**／特定トリガーへの定型回答・CTA → **応答ルール**
6. 期間限定の告知 → **お知らせ**／画像・PDF・地図・動画 → **添付メディア**
7. 上記いずれにも該当しない背景・理念・体制・制度の説明 → **ナレッジ記事**（最終手段）

### FAQタブ（よくあるご質問）に出す判定（3条件すべて）
①患者が能動的に知りたい頻出の実務質問 ②病院として能動掲示してよい ③回答が短く確定。
→ 外れるもの（背景・体制・院内ルール・治療解説）は**ナレッジ記事**（チャットでは回答されるがタブ非表示）。
- **よくある質問＝ナレッジ登録が前提**。FAQにするものは登録先に「**ナレッジ記事＋よくある質問**」と両方記載する。

## 4. 主要エンティティの必須フィールド
- **診療メニュー（必須5）**: メニュー名／別名・キーワード（1件以上）／保険種別／関連診療科（1件以上）／概要。＋（推奨）対象の悩み・使用機器・対象者像・検査内容・治療計画・施術/診療の流れ・痛み麻酔・副作用リスク・禁忌対象外・所要時間・予約要否・料金プラン・添付メディア。**必須は必ず埋める。HP未記載は `要確認`**。
- **お悩み・症状**: 名称／別名(aliases)／一般説明／主な症状／当院の治療方針(clinic_note)／関連診療科／関連メニュー。
  - **別名(aliases)＝症状・疾患の言い換えのみ**。治療名・検査名・外来名は入れない（それらは診療メニューの別名へ。お悩みとは関連メニューで紐付け）。
  - **フィールド使い分け**: 一般説明＝症状/状態の簡単な説明／主な症状＝具体症状／当院の治療方針＝対応科・治療・受診/ページ誘導（長い案内文はここ。一般説明に入れない）。
- **応答ルール（特殊トリガー限定）**: ルール名／適用範囲／回答タイプ／**CTAボタンは1つ（遷移先URL1件）**／本文／質問例5〜10／キーワード10前後／優先度。誘導先が複数なら応答ルールを分割。
- **よくあるご質問**: 質問（〜500字）／回答（〜20000字）／カテゴリ。

## 5. 応答ルールの使いどころ（増やしすぎない）
疾患・症状を応答ルールにしない（無限に増えて破綻）。応答ルールは次の特殊トリガー限定:
- 救急エスカレーション（緊急サイン→119/救急相談へ。疾患名の推定は出さない）
- 連絡先・予約の出し分け（紹介状有無で窓口が違う 等）
- 医療判断の回避（診断/治療要否は受診誘導）
- 言い換えが膨大な確認系（「○○先生は今日いますか」→最新ページ誘導）

## 6. 応対分類A（疾患・治療ページ）の設計
1. **回答は概要＋誘導のみ**（詳細・適否判断しない）。
2. **第一登録先はお悩み・症状**（応答ルールにしない）。
3. 質問バリエーションは①症状語②疾患名/別名 を**お悩み・症状の別名**に。治療名/検査名は**診療メニューの別名**に入れ、関連メニューで結ぶ。
4. 疾患ページ配下の子ページ: **専門外来→診療メニュー／重症型・関連疾患→親お悩みに統合／検査・治療の詳細→誘導**（個別エンティティを増やさない）。

## 7. 重複・整合・動的データ
- **テーマ単位で1件に統合**（ページ単位でなく）。同テーマが複数ページに出ても1件。新規前に既存・公開済みと突き合わせる。
- **一般原則は特定ページ配下に限定しない**（例: 保険適用外は入院に限らず汎用ナレッジに）。
- **動的データ（休診/担当表/イベント日程/メニュー）は本文に埋め込まず最新ページへ誘導**。
- **料金表など個別に金額を聞かれるものは、FAQに代表例・ナレッジに全件**（RAGで個別回答可能に）。
- 既存データと矛盾（電話番号・時間等）は `要確認` に明記。

## 8. 出力フォーマット（1ページごと）
シンプルな表で出す（横に広げない）:

| 質問 | 回答（患者向け完成文・です・ます調・概要＋プレーンURL） | 登録先（機能名／状態） |

- 登録先は管理画面の**日本語機能名**（JSONキー名は使わない）。状態は 🆕新規 ／ 📦既存候補あり（管理画面反映は要確認）。
- 表の下に **根拠（HP該当箇所）・要確認・処理したセクション一覧（漏れチェック）** を箇条書き。
- 「ナレッジ記事に振り分け」としたものも**本文まで作成**する（ラベルで終わらせない）。

## 9. 1ページの作業フロー
1. ページ本文を通読し、**ページ内目次（見出し）を一覧化**して全セクションを処理対象に（飛ばさない）。
2. §3の優先順位で各情報をエンティティに仕分け。
3. 既存データと突き合わせ（重複は統合、矛盾はフラグ）。
4. §8の形式で出力（必須項目を必ず埋める）。
5. 末尾に要確認リストと処理セクション一覧を付ける。

## 10. 先方（クリニック）への質問の記録
HP未記載・方針未確定・矛盾など先方回答が必要な事項は、別途リスト（例: `client-questions.csv`＝ `# / カテゴリ / 質問事項 / 回答`）に追記。1件ごとに対象（どのページ/エンティティ起因か）を含める。

## 11. 質問観点チェックリスト（HP抽出で漏れやすい・全案件共通）
HPは「やっていることの紹介」中心のため、患者が実際に聞く質問は多くが未記載。各ページ処理の最後と総仕上げで、下記16観点を当てて漏れを潰す（実運用ログ分析より）。
1. **対応可否（やっている/やっていない）★** 「◯◯できますか？」。やっていない診療はHPに無く全漏れ→近接診療を先回りで**診療対象外テーマ**に。
2. **個別品目の料金★** 銘柄/薬剤/検査単体/書類ごとの具体額→料金プラン＋全件ナレッジ。
3. **保険/自費の切り分け** 4. **初診料・再診料の有無** 5. **予約メニューの選び方★（予約連携特有）**
6. **受診資格・条件★**（年齢/保護者同伴・性別・生理中・妊娠週数・かかりつけ・保険証・対象エリア）
7. **診察・処方の要否**（診察なしで薬だけ/処方のみ/再診要否/処方箋切れ）8. **他院連携・引き継ぎ**（連携先有無は要確認）
9. **薬の可否＝医療判断回避**（医師判断→受診）10. **書類・証明の発行**（再発行/同意書PDF/捺印）
11. **検査結果の受け取り方**（電話/来院/アプリ・日数）12. **手続き・システム操作★**（LINE/問診票/履歴/定期便：導入時に先方確認）
13. **持ち物・所要時間・服装** 14. **キャンセル・変更ルール**（特別枠は分けて登録）15. **プライバシー配慮**（親/家族通知・郵送物）
16. **繁忙期・特例営業／設備アクセス**（GW・年末年始→お知らせ／バリアフリー・授乳室・駐輪場・マイナ保険証）

## 12. 電話フォールバックを最小化する（最重要メタルール）
「わからない＝お電話ください」は電話を増やすアンチパターン。各FAQで「電話に流していないか？対応外明示 or リンク完結にできないか？」を自問し、次の順で処理:
1. 対応していないなら「対応していません」で完結（＋代替受診先）。2. 公開情報はリンク/定型で完結。3. 医療判断・個別性のみ受診/電話（＋なぜ電話かを添える）。4. 緊急・受入不可は先に切り分け提示。
※紛らわしい品目/場面（吐き気止め↔痛み止め 等）は別名・キーワードで分離し別FAQに。一般原則は場面限定で書かず横断FAQに。

## 13. クリニック共通ベースFAQ枠（新規案件の必須埋め枠）
診療科が違っても骨格は共通。まず下記枠を用意しHP事実を流し込む（空欄は要確認で先方へ）:
A.受診・予約 / B.料金・支払い / C.対応範囲（やっていない診療含む）/ D.受診資格・条件 / E.アクセス・設備・営業（繁忙期特例）/ F.検査・結果の受け取り / G.書類 / H.デジタル手続き / I.プライバシー / J.医療判断・緊急。
