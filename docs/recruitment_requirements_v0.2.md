## 1. サービス位置づけ

### コンセプト

**SuguDesk = 採用業務の代行管理システム + BPO**

```
┌────────────────────────────────────────┐
│ 代行管理システム（候補者DB・AI支援・院向UI）│
│  - 候補者進捗の一元管理                  │
│  - AI支援機能（院・オペ双方が使える）    │
│  - 月次レポート                          │
└────────────────────────────────────────┘
                 +
┌────────────────────────────────────────┐
│ BPO（弊社オペによる業務代行）            │
│  - 媒体運用、紹介会社折衝               │
│  - データ取り込み、スカウト送信         │
│  - 院長/事務長が「やらないこと」を全部 │
└────────────────────────────────────────┘
```

### 競合との差分（HERP等のATSとの違い）

| 観点 | HERP Hire / 一般のATS | SuguDesk |
|---|---|---|
| 使う人 | 企業の採用担当者 | 弊社オペ + 院長/事務長（限定機能） |
| 業界 | ホリゾンタル（全業界） | クリニック特化 |
| 提供形態 | SaaS（ツール提供） | 業務代行サービス（人＋ツール） |
| 院長/事務長の負荷 | 自分で全部触る | 結果だけ受け取る + AI支援機能を使う |

## 2. シンプル原則（v0.2 新規）

クリニックは中小規模、ステークホルダーは事務長または医師1名が前提。複雑なATSの機能群をそのまま持ち込まないこと。

| 原則 | 意味 |
|---|---|
| **1人で完結** | 事務長または医師1名が単独で使う前提でUI設計 |
| **複数ステークホルダー前提の機能は外す** | スクラム採用・Slack統合・タレントプール・リファラル採用機能等は不要 |
| **1画面で「今やること」が見える** | ダッシュボードが「判断待ち◯件」「面接予定◯件」をワンビュー |
| **AI提案 → 1クリック実行** | 操作回数を最小化、AIが提案して人が承認 |
| **削るべきは削る** | 「あった方が便利」程度の機能は載せない |

---

## 3. ステークホルダー

| 役割 | 概要 | 期待値 |
|---|---|---|
| **院長** | クリニック責任者、採用最終判断者 | 採用業務から解放される、結果が見える、必要なときAIを使える |
| **事務長** | 院長配偶者など、運営担当 | 院長と同等の情報・操作権限、面接準備や振り返りで実際に使う |
| **SuguDeskオペレータ** | サービス提供側、複数院担当 | 効率的に複数院を運用できる |
| 候補者 | 媒体経由・紹介会社経由 | システム外部、SuguDesk側に直接アクセスしない |
| 媒体 | Indeed・ジョブメドレー等 | システム外部、メール・CSV経由でデータ取得 |
| 紹介会社 | マイナビ・レバウェル等 | システム外部、メール・電話で連携 |

## 4. サーフェイス（提供面）

SuguDeskは4つのサーフェイスを持つ：

### A. 院（事務長/医師）向け管理画面
- シンプル・1人で完結
- AI支援機能（面接質問・振り返り・連絡文依頼）
- 候補者進捗の閲覧（一部操作）
- 月次レポート閲覧

### B. オペ向け管理画面
- 業務代行のための内部ツール
- 全院横断、データ取り込み、テンプレ管理
- AI支援フル機能

### C. 院長LINE通知
- 受動的、即時性
- 「応募1件」「面接予定」「採用確定」等

### D. メール/CSV自動取り込み
- バックエンド処理
- 媒体・紹介会社からのデータを自動構造化

## 5. 業務フロー（ユースケース定義）

v0.1から実質変更なし。詳細は v0.1 文書を参照。

主要ユースケース：
- UC-1：求人原稿の作成・媒体掲載
- UC-2：媒体への直接応募が発生
- UC-3：スカウト戦略の月次設計
- UC-4：スカウトの実送信（バルク前提）
- UC-5：スカウト実績の月次取り込み
- UC-6：スカウト返信が発生
- UC-7：紹介会社からの候補者紹介
- UC-8：書類選考
- UC-9：面接日程調整
- UC-10：面接実施
- UC-11：採用判断・採用通知
- UC-12：不採用通知
- UC-13：紹介会社への要望伝達・フィードバック
- UC-14：月次レポート生成・配信

### v0.2 追加ユースケース

#### UC-15：院長/事務長が面接質問を準備
**いつ**：面接前
**主担当**：院長 or 事務長
**フロー**：
1. 院向け管理画面で「🎤 面接質問の準備」を選択
2. 面接予定の候補者を選択
3. AIが候補者プロフィール（経歴・職種）と院の特性から質問例を生成
4. 院長/事務長が確認、必要なら編集
5. 印刷 or スマホで参照

#### UC-16：院長が面接の振り返り
**いつ**：面接後
**主担当**：院長 or 事務長
**フロー**：
1. 院向け管理画面で「📝 面接の振り返り」を選択
2. Zoomの書き出しファイル（.vtt/.txt/.mp4/.m4a）をアップロード
3. AIが文字起こし（必要なら）→ 要約 → 候補者の強み・弱み抽出 → 評価ドラフト生成
4. 院長/事務長が編集・保存
5. ステータスが自動で「面接実施」に更新、評価ドラフトはオペにも共有

#### UC-17：院長が候補者への連絡を依頼
**いつ**：採用通知・追加質問への回答等、院長が直接候補者に何か伝えたいとき
**主担当**：院長 → オペが代行
**フロー**：
1. 院向け管理画面で「💬 候補者への連絡を依頼」
2. 候補者選択 → シーン選択（採用通知/質問への回答/その他）→ 要望を自由記述
3. オペにアラート、AIが下書きを生成、オペが磨いて院長承認を取る
4. 院長承認後、媒体経由で送信

## 7. データモデル（v0.2）

v0.1のモデルに以下を追加：

```
[InterviewArtifact 面接成果物] ← 新規
- id, case_id
- type (question_prep / debrief)
- artifact (テキスト・要約・評価ドラフト)
- created_by (院長 or オペ)
- ※候補者個人情報は含めない（媒体内匿名IDのみ参照）

[CommunicationRequest 連絡依頼] ← 新規
- id, case_id, scene
- request_text (院長の要望)
- ai_draft (AI生成下書き)
- final_text (オペ調整・院長承認後の最終文)
- status (依頼中/オペ作成中/院長承認待ち/送信済み)
```

## 8. 機能要件（v0.2）

### 業務代行 + システム の機能（v0.1から）

- F-1: メール取り込み（応募・スカウト返信）
- F-2: 紹介会社メール取り込み
- F-3: スカウトテンプレ管理
- F-4: スカウト実績取り込み（CSV）
- F-5: 案件進捗管理（カンバン）
- F-6: 院長判断のイベント記録
- F-7: 紹介会社管理
- F-8: 月次レポート生成
- F-9: 院長/事務長への通知
- F-10: 求人原稿管理
- F-11: 媒体・紹介会社ROIダッシュボード

### AI支援機能（v0.2 新規）

#### F-12: AI面接質問提案（院向け）
- 候補者プロフィール × 院の特性 から質問例を5-8件生成
- 業種別観点を含める（婦人科：分娩経験、美容皮膚科：施術経験等）
- 印刷可・スマホ閲覧対応

#### F-13: AI面接振り返り（院向け）
- Zoomの書き出しファイル（.vtt/.txt/.mp4/.m4a）をアップロード
- 文字起こし（mp4/m4aの場合）+ AI要約 + 強み弱み抽出 + 評価ドラフト
- 編集・保存後、ステータス自動連動、オペにも共有

#### F-14: AI候補者連絡文生成
- **オペ向け本機能**：シーン選択 → AI下書き → オペ調整 → 院長承認 → 送信
- **院向け「依頼」ボタン**：候補者選択 + シーン選択 + 要望記述 → オペに依頼

### サーフェイス機能（v0.2 新規）

#### F-16: 院向け管理画面
- 認証：パスワード or マジックリンク
- 構成：
  - 今日のアクション（判断待ち件数、面接予定）
  - 進行中の案件（簡略カンバン or リスト）
  - AI支援メニュー（F-12, F-13, F-14の依頼）
  - 月次レポート閲覧
- 個人情報：媒体内匿名IDのみ表示

### 削除・除外

- ~~F-15（引き継ぎメッセージ整形）~~ シンプル原則に従い削除
- F-17（AIアシスタントチャット）は v0.2 では除外（オペ向けは将来検討）

## 9. 提供価値（院長/事務長視点）

### 院長/事務長が見るもの・使うもの
1. **採用ファネルの可視化**：応募→書類→面接→採用、媒体・紹介会社別比較
2. **媒体別ROI**：どこが効率いいか、予算配分の最適化提案
3. **紹介会社の比較**：どこが質の高い候補者を出すか
4. **進行中の案件**：今何件が判断待ちで、何件が面接予定か
5. **AI支援機能**：面接準備（質問提案）、振り返り（Zoom→要約）、連絡依頼

### 院長/事務長がやること
1. 求人原稿・スカウト文面の承認（月数回）
2. 書類選考の通過/不通過判断
3. 面接実施
4. **AI支援機能で面接準備・振り返り（任意・新規）**
5. 採用判断
6. 月次レポート確認・MTG

### 院長/事務長がやらないこと
- 媒体管理画面ログイン
- 求人原稿・スカウト文の作成
- 応募者・候補者への一次返信（連絡文の最終承認のみ）
- 媒体別効果計算
- 紹介会社との折衝
- 不採用通知作成
- スカウト送信
- 個人情報の取り扱い

## 10. 非機能要件

v0.1から変更なし：
- 個人情報非保持
- 通知の即時性
- 媒体規約準拠
- 法規制（個人情報保護法・職業安定法）対応

### Zoom連携の追加注意点

- 候補者の同意の上でZoom録画する運用ルールを院側に案内
- アップロードファイルは保存期間を限定（採用判断後30日等）
- 文字起こし結果のみ保持、元ファイルは破棄
