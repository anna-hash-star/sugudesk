# データ取得実現性 検証メモ v0.1

> SuguDesk 採用業務代行のMVPで前提にしている「メール・CSV経由でのデータ取得」が、現実の主要媒体・紹介会社で本当に動くかを検証するためのメモ。
> 「これ実際取れるのか？」という事業上の不安に対する **PoC計画と現状の確からしさの整理**。

---

## 1. データ取得手段の整理

| 取得手段 | 自動化 | リスク | 取得できるデータ |
|---|---|---|---|
| **A. メール通知のAIパース** | ◎ 完全自動 | 低 | 応募・スカウト返信・紹介会社からの推薦通知 |
| **B. CSV/Excelエクスポート（公式機能）** | △ オペが月次操作 | なし | スカウト送信履歴・応募者一覧・選考履歴 |
| **C. 公開API・フィード連携** | ◎ 完全自動 | なし | Indeed、求人ボックス、スタンバイ等 |
| **D. ブラウザ自動化（Playwright/RPA）** | ◎ 完全自動 | **高（規約）** | 全データ |
| **E. オペが管理画面で目視確認** | ✕ 手動 | なし | 全データ |

**MVP（Phase 0-1）は A + B + 一部 C** に閉じ、D/E はバックアップ。

## 3. メール通知で取れる情報の実態

### 取れるもの（高い確度）
- 媒体名（送信元から判別可）
- 応募イベントの発生時刻
- 応募者の媒体内ID（or 仮名）
- 応募求人タイトル
- 応募職種

### 取れないもの／取りにくいもの
- 応募者の詳細プロフィール（媒体管理画面でログイン参照が必要）
- 給与希望の詳細
- 履歴書添付（プライバシー観点でも保存しない方針）
- 媒体掲載費の明細（請求書 or CSV別途）

→ MVPで必要なのは「**媒体別の応募数・スカウト送信数・返信数の集計**」なので、取れる範囲で十分。

## 4. 不安要素と対応策

### 不安1: 媒体ごとの通知メール仕様が不明
**対応**：
- 主要4媒体（Indeed・ジョブメドレー・看護roo!・マイナビ看護師）の **実通知メールサンプルを既存7院から収集**
- AIパース精度を検証
- 失敗ケースは管理画面でオペが補完（PoC段階で許容）

### 不安2: 媒体側のメール仕様が予告なく変わる
**対応**：
- 月次CSVエクスポート（B手段）で **整合性チェック**
- 不整合検知時にオペアラート
- 媒体別パーサーを独立実装、影響を局所化

### 不安3: 紹介会社のメールフォーマットが多様すぎる
**対応**：
- AIで構造化（Claudeのstructured output等）→ パターンを問わず抽出
- 確信度低の場合はオペレビュー必須
- よく使う紹介会社は専用パーサー（テンプレベース）

### 不安4: スカウト送信実績の取得
**対応**：
- 各媒体の **「スカウト送信履歴CSVエクスポート」機能** をオペが月次取り込み
- ジョブメドレー・看護roo! など主要媒体には公式機能あり
- 集計値（送信数・開封数・返信数）が取れれば十分

### 不安5: 媒体掲載費の取得
**対応**：
- 請求書PDF or 月次CSV をオペが手入力 or AIパース
- 月1回の作業で許容範囲

## 5. PoC計画（事業を進める前に検証すべきもの）

### Phase A：メール仕様確認（2週間）
- 既存7院から **直近1ヶ月の通知メールサンプル収集**（医院の許可取得）
- 媒体別にメールフォーマットを目視確認
- AIパースのプロンプトを試作
- 取れるフィールドと取れないフィールドを確定

### Phase B：CSV取り込み検証（2週間）
- ジョブメドレー、看護roo! の管理画面でスカウト履歴CSVを実際にエクスポート
- AI解析プロンプトを試作
- 個人情報除去後の集計値が正しく出るか検証

### Phase C：実運用ドライラン（1ヶ月）
- 1院（Luna LadiesかAdeB）でフル運用ドライラン
- メール転送 → AIパース → ダッシュボード表示
- 月末CSV取り込み
- 取りこぼし・誤検知を計測

### 判定基準
- メールパース精度 90%以上 → MVP実装に進む
- 80-90% → オペ補完を前提にMVP進む
- 80%未満 → メール+CSVで足りない、別の方法（RPA等）を検討

---

## 6. 結論：現実性の評価

**取れる範囲で MVP は成立する** と評価。

理由：
1. メール通知は **どの主要媒体・紹介会社でも提供されている**（応募・スカウト返信時）
2. CSVエクスポートも **主要媒体に存在する**（公式機能）
3. **個人情報非保持の設計** なので、取得すべきデータは集計値のみ → ハードル低い
4. AIで多様なメールフォーマットを構造化できる時代になっている

ただし以下は **PoC で確認** が必要：
- 各媒体のメール文面を見たことがない
- ジョブメドレー、看護roo! の管理画面を実際に触っていない
- 紹介会社のメールフォーマットの多様性が想定以上の可能性
