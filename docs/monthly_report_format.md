# SuguDesk 月次レポートの型（v2）

最終更新: 2026-07-08

月次でクリニックに届けるアウトプットの「型」を定義する。
旧仕様（`reports_spec.md` の①簡易レポート／②月次レポート／③改善チェックシート）を見直し、
**「メール1通＋添付」に収まるシンプルな型** に再整理したもの。

方針の変更点:

- スタンダードとプレミアムのアウトプットは **同一** にする（プレミアムだけの特別レポートは作らない）
- スタンダード以上のレポートは **リッチに作り、示唆まで出す**。いまのルナ様月次レポートの構成をベースに、会話ログの流入・端末データを使った分析を加える
- ライトはメール本文のテキストサマリのみ。**メール本文だけで先月の状況がわかる** ようにし、そのうえでダッシュボードのリンクを必ず添える（先生はダッシュボードを見ないかもしれない前提）

---

## 1. プラン別マトリクス

| | ライト | スタンダード | プレミアム |
|---|---|---|---|
| メール本文（テキストサマリ） | ○ | ○ | ○ |
| 月次レポート添付（PDF もしくは Word・示唆入り） | — | ○ | ○ |
| FAQ修正リスト添付 | ○ | ○ | ○ |
| ダッシュボードリンク | ○ | ○ | ○ |

- **ライト**: メール本文のテキストサマリ＋FAQ修正リスト添付。それだけ。
- **スタンダード／プレミアム**: 上記に加えて、示唆入りの月次レポートをPDF（もしくはWord）で添付。ルナ様月次レポートの構成＋流入・端末分析。

毎月の送付物は「メール1通」。本文で完結し、詳しく見たい人だけ添付とダッシュボードへ進む構成。

## 2. メール本文（全プラン共通のテキストサマリ）

先月のサマリはダッシュボードの数字をそのまま使う。テンプレート:

```
件名: 【SuguDesk】{クリニック名}様 {YYYY年M月} 月次レポート

{クリニック名} {担当者名}様

いつもお世話になっております。SuguDeskサポートです。
{M}月のチャットボット利用状況をお送りします。

■ {M}月のサマリ（前月比）
・会話数           : {総会話数}件（{±n}件）
・AIの自己解決率    : {自己解決率}%（{±n}pt）
・未回答           : {未回答件数}件
・削減できた対応時間 : 約{削減対応時間}分（人件費換算 約¥{削減コスト}）

■ よく聞かれた質問 TOP3
1. {質問テーマ1}（{n}件）
2. {質問テーマ2}（{n}件）
3. {質問テーマ3}（{n}件）

■ ご確認のお願い（5分ほどで終わります）
AIがうまく答えられなかった質問を「FAQ修正リスト」にまとめて添付しています。
黄色の「ご回答（記入欄）」だけご記入のうえ、ご返信ください。
いただいた回答は弊社でFAQに反映し、翌月の自己解決率の改善につなげます。

■ 詳しい数字はダッシュボードでいつでもご覧いただけます
{ダッシュボードURL}

添付:
・FAQ修正リスト（Excel）
・月次レポート（PDF）※スタンダード・プレミアムのみ

──
{署名}
```

使う数字とダッシュボードの対応:

| 本文の項目 | ダッシュボード上の表示 |
|---|---|
| 会話数 | 総会話数（前期比つき） |
| AIの自己解決率 | 自己解決率（前期比つき） |
| 未回答 | 未回答 |
| 削減できた対応時間／コスト | AI対応の効果（削減した対応時間・削減したコスト） |
| よく聞かれた質問 TOP3 | 上位 質問テーマ TOP5 の上位3件 |

> 生成は「対象月の30日ビュー」の数値をそのまま転記するだけでよく、CSの編集は原則不要。
> ライトはこの本文＋FAQ修正リスト添付で完成（自動送信でもよい）。

## 3. 月次レポート添付（スタンダード／プレミアム、PDF もしくは Word）

**リッチに作り、示唆まで出す。** いまのルナ様月次レポート（運用レポート）の構成をベースに、
会話ログの流入・端末データを使った「どこから・どんな環境で聞かれているか」の分析を新設する。
詳細スキーマは `reports_spec.md` Part 2（`monthly_report`）を参照。

### ページ構成

1. **今月のハイライト**（数字4つ＋前月比）
   - 総会話数／自己解決率／未回答／削減した対応時間・コスト
2. **利用状況の推移**（ルナ様レポート準拠）
   - 回答率トレンド（導入以来の推移）／日別・時間別会話数／週別回答率
   - 「貴院のご回答→改善効果」（FAQ反映前後の回答率比較）
3. **患者様の傾向と示唆**（ルナ様レポート準拠）
   - 曜日別・時間帯別・話題別の分布／診療メニュー別マトリクス
   - **示唆①〜＋→提案**（頻度×回答率×時間帯などから抽出し、提案文まで出す）
4. **流入・端末分析（新設）** — 会話ログの流入・端末メタデータから集計
   - どのページから質問が多いか／端末別の内訳（詳細は 3-1）
5. **患者様の声・会話例**
   - 回答評価（Good・Bad件数、満足度%）／AIが良い回答をできた代表例
6. **FAQ修正の進捗と今月のお願い**
   - 先月いただいた回答の反映状況（例: 12件反映済み → 自己解決率 +2.1pt）
   - 今月のFAQ修正リストの件数と、特にご確認いただきたい点（1〜3個）

### 3-1. 流入・端末分析の中身

会話ログに記録済みのメタデータ（流入元ページ／参照元ドメイン／utm_source・medium・campaign・term・content・id／
端末／ブラウザ／画面サイズ／ブラウザ言語／会話開始日時／初回発話までの秒数／CV種別）を月次で集計する。

| ブロック | 集計 | 出したい示唆の例 |
|---|---|---|
| ページ別会話数 TOP5 | 流入元ページ × 会話数 × 主な質問テーマ × 回答率 | 「/campaigns/ からテノールネオの施術間隔の質問が多い → キャンペーンページに間隔・回数の記載を足すと問い合わせが減る」 |
| 参照元・キャンペーン別 | 参照元ドメイン／utm_source・campaign × 会話数 × CV種別 | 「広告経由の来訪者は料金の質問が中心 → 広告LPに料金目安を明記」 |
| 端末別内訳 | 端末（mobile/desktop等）× 会話数 × 回答率 | 「9割がモバイル → ウィジェットの導線・文字量はモバイル前提で調整」 |
| 利用タイミング | 会話開始時刻の分布／初回発話までの秒数 | 「診療時間外の利用が◯% → AIが時間外の一次対応を担えている」 |

> ページ×質問テーマのクロスが示唆の主戦場。「このページにこの情報を足すと問い合わせ自体が減る」
> という **HP改善提案** につなげる（ルナ様レポートの示唆④系統を流入データで裏づける位置づけ）。

## 4. FAQ修正リスト（全プラン共通・Excel添付）

実際に運用している2つの実物をベースに統一する。

- **クライアント記入面**: AdeBクリニック「確認フォーム」の形式（記入欄だけ埋めて返せばよい）
- **社内管理**: ルナレディース「チャット修正シート」の運用（起票日・優先度・ステータス・対応日）

### クライアントに見せる列（AdeB確認フォーム準拠）

| 列 | 記入者 | 説明 |
|---|---|---|
| # | 自動 | 連番 |
| カテゴリ | CS/AI | 施術・領域単位（例: A. テノールネオ） |
| ご確認いただきたい内容 | CS/AI | 確認したいことを質問文で |
| 患者さんからの質問例（実際の声） | AI | 実際の会話ログからの原文 |
| **ご回答（記入欄）** | **クリニック** | 黄色背景。ここだけ書いて返してもらう |
| 対応状況 | CS | 未対応／確認中／FAQ追加済み／FAQ修正済み／対象外 |
| 備考 | CS | |

### 社内で持つ管理列（ルナ チャット修正シート準拠、先方には見せない）

起票日／回答優先度（高：売上直結・緊急・頻発、中、低）／ステータス／対応メモ／対応日。

### 運用ルール（現行のまま）

- 色分け: **黄色＝クリニック記入欄**、白＝CS記入欄
- 返送された回答はCSがFAQに反映し、対応状況を更新
- 反映結果は翌月のメール本文・サマリ添付の「FAQ修正の進捗」で報告する（協力→改善→報告の循環）

## 5. 月次の流れ

```
月初  →  ダッシュボードの数字からメール本文（＋PDFサマリ）を生成
      →  当月のFAQ修正リストを生成（未回答・要改善の会話から抽出）
  ↓
CSが確認・手直し（ライトはスキップ可）
  ↓
メール送付（本文＋添付: FAQ修正リスト、スタンダード以上はPDFサマリも）
  ↓
クリニックが「ご回答（記入欄）」を埋めて返信
  ↓
CSがFAQへ反映 → 翌月のレポートで「反映しました・改善しました」と報告
```

## 6. 旧仕様（reports_spec.md）との関係

| 旧仕様 | 本書での扱い |
|---|---|
| ①簡易レポート（ライト） | 「メール本文（テキストサマリ）」として全プラン共通化 |
| ②月次レポート（ルナ第3回準拠のリッチ資料） | 継続・拡張。PDF/Word添付とし、**流入・端末分析（3-1）を新設**。示唆＋提案は維持 |
| ③改善チェックシート | 「FAQ修正リスト」として継続（実物準拠。6区分などの内部スキーマは reports_spec.md Part 2 を参照） |
| プレミアム専用の院別レポート | 廃止（スタンダードと同一アウトプット） |
